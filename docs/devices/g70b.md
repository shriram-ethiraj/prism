# Samsung Odyssey G70B compatibility

Verified configuration: **LS28BG702EWXXL / T-PTMLWWC-1720.7**. Physical results apply to Prism **0.2.6 / 0.2.7**, tested on **27 October 2026**. See the [device registry](../../VERIFIED_DEVICES.md) and [setup guide](../setup.md). Other firmware and later Prism builds require separate validation.

## Setup requirements

- Tizen 6.5, Chromium 85, ARMv7, Microsoft.NETCore.App 3.1.3 and non-root SDK UID 901. Setup must confirm the actual firmware, architecture, runtime and privilege context before native operations.
- The verified logical app surface is 1920×1080. Panel/video resolution is separate. Overflow can inflate `innerWidth` and `visualViewport`; use the verified native surface profile rather than those inflated measurements.
- Inputs observed on this model: DisplayPort 1, HDMI 1 and HDMI 2. Discovery uses SystemInfo VIDEOSOURCE; preserve the returned descriptors. TVWindow source switching hands video back to Samsung's native `org.tizen.tv-viewer`.
- App discovery uses the Application API. Prism's stable application ID is `Prizen0001.Home`. Samsung Home is `com.samsung.tv.csfs`; the native Settings destination is `com.samsung.tv.coba.setting`. Destination availability must be checked on the target device.
- Foreground navigation codes: Enter 13, Left/Up/Right/Down 37–40 and Back 10009. Foreground handling does not remap the physical Home button globally.
- Enable Developer Mode through Apps → App Settings → 12345. An alternative long-press Home → number mode → 12345 gesture was reported for the reference remote but remains pending a fresh physical check.

## Home/startup integration and recovery

Setup runs a bounded, short-lived .NET helper through the developer connection as SDK UID 901. This uses undocumented platform behavior and may stop working after a firmware update. No root or resident watcher is required. Each installation needs its own external private baseline and restoration checks; keep the existing fallback app installed.

The profile and native helper use these interfaces:

- `aul_get_default_app` in `libaul.so.0` reads the Home operation. `app_operation_set_current_app` in `libcapi-appfw-app-operation-tv.so.0` assigns `http://tizen.org/appcontrol/operation/main`.
- `libvconf.so.0` string/int APIs read and write `db/appfw/home_appid`, `db/appfw/startup_appid` and `db/menu/smart_hub/ontvsetting/auto_start`.
- `util_is_appbooting_supported_webapp_byappid` in `libapp-context-manager-common.so` checks startup eligibility.
- `db/appfw/booting_appid_backup` and `db/first_screen/type` are platform-managed, read-only observations. They may change across app launches and are excluded from assignment comparisons and restoration writes.

Home and startup are separate guarded transactions with immediate readback and rollback. Owned-setting mismatches must stop the operation; never overwrite the original baseline or weaken guards to force a retry. A rapid restore/reapply stress check encountered such a mismatch and rolled back safely; the initiating actor was not established. A subsequent guarded apply succeeded.

## Verified physical results

All observations below were recorded on 27 October 2026 for the exact configuration above. Readbacks and physical observations are separate evidence.

| Prism build | Check | Result |
| --- | --- | --- |
| 0.2.6 | Installation and fullscreen | Signed installation and running/visible readback passed; Home and Settings were physically confirmed without zoom, cropping or blank areas. |
| 0.2.6 | Apps, inputs and physical Home | App/input opening and Home return were confirmed from a streaming app and connected DisplayPort input. The streaming app name was not recorded. |
| 0.2.6 | Standby and cold boot | Remote off/on and monitor-only power disconnect/reconnect opened Prism. A transient empty-state prompt during discovery was observed. |
| 0.2.7 | Cold-boot presentation | A fresh monitor-only cold boot showed cached startup tiles without the incorrect Open Settings prompt. |
| 0.2.7 | Samsung escape routes | Samsung Home and Settings opened from the System controls present in that build; physical Home returned to Prism after each. |
| 0.2.7 | Recovery | Original Home/startup settings were restored with exact readback; physical Home opened the previous launcher. Guarded reapplication succeeded, and final owned-setting readbacks matched the saved Prism plan. |

These results do not establish physical acceptance of later UI builds, other monitors, other firmware, a 4K logical surface, or firmware-update compatibility. No launch-time, game FPS, input-latency, resource-saving or endurance benchmark is claimed. Private signing material, device identifiers and restoration records are never part of this profile.
